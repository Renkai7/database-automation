<objective>
Apply the gate to the live repository, prove — by performing it — that the owner cannot walk around
it, and write the record from what actually happened.

Purpose: this plan closes CI-03 (D-04's ruleset applied and self-checked) and the phase's first
success criterion. D-18 requires the owner to perform the merge attempt personally, because no test
can assert criterion 1 from inside the system: it is a claim about what GitHub refuses to do for a
specific human account. This follows `02-CONTEXT.md` D-10's precedent exactly — the restore runbook
was written from a performed restore, not from documentation prepared in advance. D-05's continuous
assertion and D-18's one-time performed proof are a deliberate pairing, not redundant: D-18 proves
the property was true once, by observation; D-05 keeps proving it.

**Sequencing the executor must not reorder.** The ruleset is applied only after the full job set has
reported at least once on a real pull request, so the six required contexts are copied from verbatim
reported names rather than guessed. 05-RESEARCH Pitfall 2 documents that a context matching no job
shows as perpetually "Expected" and blocks every future pull request with no error pointing at the
cause.

**Working-mode change from this plan onward.** Once the ruleset is active, `git push origin main` is
refused. Local commits continue exactly as before; publishing them requires a branch and a pull
request whose six checks pass. This applies to this plan's own documentation commits and to every
subsequent GSD phase in this repository. That is D-04's recorded consequence, accepted rather than
worked around.
</objective>
