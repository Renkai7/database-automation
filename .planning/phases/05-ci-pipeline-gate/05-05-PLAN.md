<objective>
Turn "the bypass list is empty" from a setting somebody remembers clicking into a committed
artifact plus a check that keeps proving it.

Purpose: CI-03 via D-04, and D-05. `.planning/research/ARCHITECTURE.md`'s bypassability ranking is
the source: classic branch protection is admin-bypassable by default; a repository ruleset with an
empty bypass list is the mechanism that makes the owner's own admin permissions insufficient —
which is this phase's goal sentence. D-05 then applies `04-CONTEXT.md` D-15's move one layer up:
the runner does not trust that it set its own timeouts, it re-queries `pg_settings` and refuses if
they do not read back as pinned, so the pipeline should not trust that the ruleset is still
configured correctly either.

**Its honest limit, stated wherever it is described:** the check runs inside the thing it audits.
Someone who can edit the ruleset can also delete the check. It raises the cost of tampering and
makes it visible; it does not make it impossible. That is `docs/decisions.md` D12's bypassability
spectrum, and this check sits on it like every other gate upstream of the runner.

Output: the committed payload, an idempotent apply script, and a fail-closed self-check with
fixture tests. **This plan does not apply the ruleset to the live repository** — plan `05-08` does
that, after the workflow has run at least once and the real reported check names are known
(05-RESEARCH Pitfall 2).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub ruleset configuration → this repository's assertion | The property being asserted lives on GitHub; only the API's answer is available, and that answer is permission-dependent. |
| committed payload → live configuration | The two can drift; nothing but the self-check notices. |
| the self-check → the ruleset it audits | The check runs inside the thing it audits. |
