<objective>
Scan every commit in this repository's history for anything that must not become public, record
the findings honestly, and get the owner's per-finding disposition — before a single commit
leaves the machine.

Purpose: D-03. Publishing is one-way. `CLAUDE.md`'s own non-negotiable forbids recording
assumptions as facts, and "nothing sensitive was ever committed and later removed" is exactly
such an assumption — nobody has verified it. Auditing only HEAD was rejected for that reason;
squashing was rejected because several phase records cite specific commit SHAs (`9f9ff0f`,
`d41954f`, `f7ff627`, `cd33399`) that would all dangle.

Output: a tested detector, a committed audit record written from real output, and a recorded
human disposition for every finding.

**This plan is the gate in front of the irreversible act, not an expansion task.** The
tracer-first slice for this phase (plan `05-03`) cannot exist until a GitHub repository does, and
`05-02` must not create one until this plan's checkpoint is answered.
</objective>

  <files>scripts/ci/audit-history.ts, tests/ci/audit-history.test.ts</files>
  <action>
    Create `scripts/ci/audit-history.ts` exporting two pure functions and one thin entry point.

    `classifyLine(line: string): string | null` returns a finding-class name for a single line of
    diff text, or null. The classes, exactly these names: `CREDENTIAL`, `NON_LOOPBACK_HOST`,
    `IP_LITERAL`, `OPERATIONAL_DETAIL`, `UNKNOWN_HIGH_ENTROPY`.
    - `CREDENTIAL` — a connection string carrying a userinfo password component; an assignment to
      a key whose name contains `password`, `passwd`, `secret`, `token` or `api_key`
      (case-insensitive) with a non-placeholder right-hand side; a PEM private-key header; a
      GitHub token prefix (`ghp_`, `gho_`, `ghs_`, `github_pat_`); an AWS access-key prefix
      (`AKIA`).
    - `NON_LOOPBACK_HOST` — a host component in a connection string or SSH-style target that is
      not one of `DEV_DATABASE_HOST_ALLOWLIST`'s four spellings. Import that constant from
      `../env` rather than re-typing the list, so the pin and the detector cannot drift.
    - `IP_LITERAL` — a dotted-quad that is not `127.0.0.1` and not in `10.`, `192.168.`,
      `172.16.`-`172.31.` private space, and not a version-number-shaped false positive (require
      four octets, each 0-255, not preceded by a digit or a dot).
    - `OPERATIONAL_DETAIL` — case-insensitive occurrence of `coolify` or `hetzner` on a line that
      also carries a host, an IP, a port, or a path (a prose mention of the platform's name alone
      is not operational detail; a server address next to it is).
    - `UNKNOWN_HIGH_ENTROPY` — a token of 32+ characters drawn only from base64/hex alphabet that
      matched no class above. This is the "cannot classify" bucket and it exists so the record can
      say UNKNOWN rather than silently pass.

    Build every literal needle at runtime by concatenation, matching
    `tests/guardrails.test.ts`'s own `["postgres", "://"].join("")` idiom — this file lives in the
    guardrail suite's source surface and must not carry the scheme prefix, `ghp_`, or `AKIA` as a
    literal substring of its own source.

    `scanHistoryText(diffText: string): Finding[]` walks unified-diff text, tracks the current
    commit SHA and the current file path from the `commit `/`+++ b/` marker lines, and returns
    `{ sha, path, lineNumberInDiff, class }` for every added line (`+` prefix, not `+++`) that
    `classifyLine` classifies. **The returned finding carries no matched text and no source line
    — only the location and the class.** This is the same "never echo the supplied value" rule
    `scripts/env.ts`'s rejection messages already hold, applied to a scanner whose input is by
    definition the thing that must not be reproduced.

    The entry point, guarded by `import.meta.main`: run
    `git log --all --full-history -p -U0 --no-color --format=%x00commit %H` (or the equivalent that
    yields a parseable per-commit marker), stream the output through `scanHistoryText`, print a
    JSON summary to stdout containing `commitsScanned`, `findings`, and `findingsByClass`, and set
    `process.exitCode` to 0 always — this is a reporting tool, not a gate; the gate is Task 3's
    human decision. Never call `process.exit()` (Windows libuv teardown crash, documented in
    `packages/automation/src/cli.ts`'s header). Read no argument from `process.argv`.

    Create `tests/ci/audit-history.test.ts` driving both functions with synthetic in-memory
    strings only — never a real commit, never a file written to disk. Cover, at minimum: each of
    the five classes fires on a crafted positive; `127.0.0.1`, `localhost`, `::1` and the pinned
    `recipe_dev` database name do NOT fire; a version string such as a four-part semver does not
    fire as `IP_LITERAL`; `.env.example`'s placeholder shape does not fire as `CREDENTIAL`; and a
    finding object contains no substring of the line that produced it.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repository → public internet | Every commit reachable from `main` crosses this boundary at once, irreversibly, in plan `05-02`. |
| commit history → audit record | The scanner reads content that must not be published and writes a record that is itself published. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Information Disclosure | git history published to a public repository | critical | mitigate | Task 1's detector + Task 2's whole-history scan + Task 3's blocking human disposition, all before `05-02` creates a remote. |
| T-05-02 | Information Disclosure | `docs/40-public-release-audit.md` itself | high | mitigate | Findings record SHA + path + class only. The record never reproduces a matched value — the same "never echo the supplied value" discipline `scripts/env.ts`'s rejection messages already hold. |
| T-05-03 | Repudiation | "we checked" with no artifact | medium | mitigate | The record is generated from real scanner output and carries the live commit count; a scan that never ran cannot produce it. |
| T-05-04 | Tampering | a detector that silently matches nothing | high | mitigate | `tests/ci/audit-history.test.ts` proves each of the five classes fires on a synthetic positive, so a broken regex fails the suite rather than producing a clean report. |
| T-05-05 | Spoofing | false confidence from a pattern-based scan | medium | accept | Recorded explicitly in the record's "Limits of this audit" section and surfaced by the `UNKNOWN_HIGH_ENTROPY` class. A pattern scanner cannot prove absence; pretending otherwise is the real risk. |
</threat_model>
