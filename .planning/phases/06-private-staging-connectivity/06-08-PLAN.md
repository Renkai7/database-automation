<objective>
Prove criterion 4 by performing it: merge a real schema change to `main`, watch it reach the staging
database with nobody touching anything, and confirm the running application never restarted.

Purpose: D-13 deployed the recipe app alongside staging precisely so this criterion could be
observed. Without a running application, "with no application redeploy" is a statement about
something that is not there, and it would carry into Phase 7 as an untested assumption. Watching
the app keep serving on an unchanged container while the schema changes underneath it is the exact
inverse of the pain point that started this project — and it is the first real-world exercise of
the bootstrap's `ALTER DEFAULT PRIVILEGES` clause, whose absence would leave the application unable
to touch the new table.

Output: an additive schema change that travels the whole pipeline, a performed end-to-end record,
and an honest close-out of this phase's requirements.
</objective>
