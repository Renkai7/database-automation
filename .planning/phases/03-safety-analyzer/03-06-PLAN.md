<objective>
Make "cannot be fooled in either direction" a structural property of the corpus rather than a claim
about how thorough the tests happen to be, and pin the verdicts the recipe app's real and reserved
schema changes will produce before Phase 4 makes any of them for real.

Purpose: phase success criterion 3 asks for adversarial fixtures in both directions. The
false-positive half is the one that quietly rots — a comment mentioning a table drop being flagged is
exactly the friction `.planning/research/PITFALLS.md` section C2 identifies as the start of the slide
toward routine overriding — so the manifest enforces the pairing rather than trusting whoever adds the
next shape to remember.

Output: five matched adversarial pairs with a structural pairing check, the app-shaped group mirroring
the reserved churn, the two genuine Drizzle migrations in the corpus, and one test that demonstrates
success criterion 1 outright.
</objective>

Add the pair-integrity check to `test/corpus.test.ts` first, before writing the fixtures, so the empty
adversarial group starts by proving the check works: group every manifest row that has a `pairId` by
that id, and assert each group has exactly two rows whose `half` values are one hidden-executable and
one inert-text-only. Report the pair id and what was missing or duplicated. This is what makes
"cannot be fooled in either direction" structural: a shape added later with only its catching half
fails the suite instead of quietly halving the coverage.

Then write ten fixtures under `test/corpus/adversarial/`, five pairs, each pair sharing a pair id and
each file carrying no classification hint in any comment.

The inline-comment pair. The executable half is a genuine table drop with a block comment written
inside the statement itself, between the keyword and the table name, so the statement still executes
exactly as written — a shape that defeats any line-oriented text scan. Expected BLOCKED. The inert half
is an ordinary safe statement, such as adding a nullable column, preceded by a line comment whose text
describes dropping a table. Expected SAFE, and no drop rule id anywhere in its findings.

The dollar-quoted-string pair. The executable half puts the real drop inside a dollar-quoted function
body. The inert half inserts a dollar-quoted string literal containing those same words as data into
an ordinary table, using a custom dollar tag so the fixture also exercises tagged quoting. Expected
not BLOCKED.

The DO-block pair. The executable half is a DO block with real control flow — a conditional around the
drop — so the recursion has to walk past a branch rather than finding the statement at the top of the
body. The inert half is a DO block that only performs safe work, such as raising a notice whose
message text mentions dropping a table.

The function-body pair. The executable half is a function creation whose body drops a table. The inert
half is a function creation whose body only returns a string constant mentioning it.

The quoted-identifier pair. The executable half drops a table whose name is a double-quoted identifier
that collides with a SQL keyword, proving quoting does not let a real drop slip past. The inert half
creates a table whose quoted name is itself the keyword phrase for dropping a table, proving that an
identifier that looks like a statement is not treated as one.

Add a manifest row for each with its pair id, half, expected verdict, expected rule ids and a `why`
sentence naming which evasion the fixture represents.
