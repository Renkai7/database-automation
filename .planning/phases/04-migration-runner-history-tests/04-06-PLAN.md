<schema_apply_requirement>
**[BLOCKING] Live schema must agree with the schema files before verification.**

This plan modifies `apps/recipe-app/src/db/schema.ts`, so the live development database must be
brought into agreement with it before anything is verified — otherwise type checks and builds
pass on types derived from the schema file while the database says something else, and the
verification is a false positive.

The generic remedy for a Drizzle project is a direct schema-sync command. **That remedy is not
used here and must not be.** This project's entire premise is that schema changes reach a
database through a governed migration runner (D12, D-01, D-02), `01-CONTEXT.md` D-11/Pitfall 3
already forbids the direct-sync sub-command by name, and `tests/guardrails.test.ts` asserts its
absence across the whole source surface — applying it would break a locked decision and a
committed structural test.

**The mechanism used instead:** `drizzle-kit generate` produces the migration, and
`pnpm db:migrate` — this phase's runner — applies it. That satisfies the underlying property
exactly (the live database really is brought into agreement with the schema files before
verification) through this project's own governed path. Tasks 1 and 2 below each carry that
apply step, and Task 3 re-runs `pnpm db:reset` so agreement is proven from an empty database as
well as incrementally.
</schema_apply_requirement>
