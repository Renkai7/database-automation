<objective>
Give the runner its transaction policy: wrapped by default, auto-unwrapped only when the file
contains a statement PostgreSQL itself forbids inside a transaction block, and refused outright
when a file mixes the two. The decision comes from the `transactionHostile` fact plan 04-02
taught the analyzer — the same parse that produced the verdict — so there is no second place in
this codebase that reasons about SQL semantics. Then prove criterion 2 against a real database:
a migration blocked on a lock another session holds fails within roughly `lock_timeout` instead
of hanging, while a `CREATE INDEX CONCURRENTLY` migration still succeeds.

Purpose: RUN-03 and RUN-04. Refusing mixed files (D-11) is what turns RUN-08 from an open
problem into exactly one named case — a failed concurrent index build leaving an INVALID index —
which plan 04-05 then handles deliberately rather than discovering.
Output: `packages/automation/src/runner/transaction-policy.ts`, its wiring into the orchestrator,
and `tests/history/timeouts-and-concurrently.test.ts`.
</objective>
