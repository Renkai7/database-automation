<objective>
Expand the tracer's assertion depth from tiers 1-2 to the full tier 1-4 set the phase
decided on: schema equality between source and restored, plus per-table content
fingerprints, named recognisable spot checks, orphan-row detection and sequence state.

Purpose: tier 3 is the tier that catches the case the manual drill is built around.
`DROP TABLE recipes CASCADE` also drops the foreign keys on `ingredients` and `steps`. After
a naive restore the rows come back, every row count matches, and an orphan-row check still
passes — only a schema comparison notices the constraints are gone. This plan asserts that
lesson generically, so the drill catches it every run without anyone remembering it.

Output: `pnpm db:drill` runs four assertion tiers, each provable in the failing direction by
its own unit test.
</objective>

  <action>
Add `canonicalizeSchemaDump(sql: string): string` and `assertSchemaEquality(pair)` to
`scripts/drill-assertions.ts`, and call the tier from `scripts/drill.ts`.

**Capturing the two dumps.** Both are taken inside `runDrill`, in the same run, seconds apart,
so ordering non-determinism between them is not in play. The source side runs
`docker compose exec -T db pg_dump -U recipe_app -d recipe_dev --schema-only --no-owner --no-acl`
via execa and captures stdout as a string. The restored side runs the same `pg_dump` flags
inside the disposable container through the restore target's `exec` method, as
`pg_dump -U <bootstrap user> -d recipe_dev --schema-only --no-owner --no-acl`, and captures its
stdout. `--no-owner` and `--no-acl` are on **both** sides deliberately: the restore uses
`--no-owner`, so objects in the restored cluster are owned by the disposable container's
bootstrap role while the source's are owned by the application role. Without both flags every
ownership and grant line would differ and the tier would be permanently red for a reason that
has nothing to do with schema equality.

**Canonicalising.** `canonicalizeSchemaDump` normalises line endings to `\n`, then removes:
lines beginning with PostgreSQL 17's restrict guard directive and its matching unrestrict
directive (these carry a random single-use token regenerated on every invocation — this is the
confirmed and only source of non-determinism between two dumps of an unchanged database);
comment-only lines, which carry dump metadata rather than schema semantics; and runs of blank
lines, collapsed to one. It returns the trimmed result. Keep the function pure and free of
I/O so it is unit-testable on string fixtures.

**Asserting.** `assertSchemaEquality({ sourceSql, restoredSql })` canonicalises both sides and
throws when they differ. Two properties are non-negotiable. First, the thrown message must
carry a bounded excerpt of the difference — the first few lines present on one side and absent
on the other, capped so the message stays readable — because "the schema differs" without
naming what differs is not diagnosable at 3am. Second, the function must reject the vacuous
case: if either canonicalised side is empty, throw naming which side was empty, rather than
concluding two empty strings are equal. That is the exact way this tier could silently stop
testing anything.

**Wiring.** In `runDrill`, run tier 3 after tiers 1-2 and before the container is stopped.
Introduce a `DrillTierResults` record in `scripts/drill.ts` tracking which tiers ran and passed
(`artifactIntegrity`, `rowCounts`, `schemaEquality`, `contentAndReferentialIntegrity`); a tier
that threw is recorded as failed and the drill exits non-zero with the failing step named.
Nothing in this plan writes that record to disk — that is plan 02-04's job.

The `<action>` above deliberately does not name the two guard directives as literal tokens;
read their exact spelling from the research file's Pattern 3 example before implementing.

Extend the manifest with three new fields captured at backup time, and add the matching
assertions.

**Manifest fields (`scripts/backup-manifest.ts`, `scripts/backup.ts`).**

- `contentHashes` — one hash per table, keyed by qualified table name, over the *whole* table:
  for each enumerated table, aggregate every row's text rendering in a stable order and hash
  the aggregate with `md5` (core PostgreSQL, no extension required). Because every primary key
  in this schema is a stored UUID rather than a generated sequence value, the row text is
  stable across a dump and restore. Aggregate an empty table to a fixed empty-string hash
  rather than SQL NULL, so an empty table produces a comparable value.
- `spotChecks` — explicitly named, non-credential column projections, so no future column can
  be swept into the manifest by accident: from `recipes`, slug with base servings and base
  kcal ordered by slug; from `ingredients`, name with quantity, unit and position ordered by
  position; from `steps`, position with timer label ordered by position. The steps projection
  is the one that proves the NULL-versus-empty-string distinction survived the round trip, so
  its serialisation must preserve SQL NULL as a null rather than coercing it to an empty
  string.
- `sequences` — every row of `pg_sequences` projected to schema name, sequence name and last
  value, ordered deterministically.

Before populating any of these, `runBackup` must require the recipe-core tables
(`recipes`, `ingredients`, `steps`) to be present, throwing with the missing table named if
they are not. A backup taken from an unmigrated database would otherwise produce a manifest of
empty comparisons that every tier passes vacuously.

**Assertions (`scripts/drill-assertions.ts`).** Add four functions, each taking a structurally
typed queryable client rather than a concrete driver class — mirror the `QueryableClient`
interface style already in `scripts/env.ts` so a unit test can pass a hand-built fake:

- `assertContentHashes(client, manifest)` — recompute each table's hash against the restored
  database with the identical query and require the key set and every value to match. A
  mismatch names the table.
- `assertSpotCheckedValues(client, manifest)` — re-run the three named projections and require
  deep equality with the manifest's recorded values. A mismatch names the table and the first
  differing row. Reject the vacuous case: an empty recorded projection for a table the manifest
  says holds rows is a failure, not a pass.
- `assertNoOrphanRows(client)` — enumerate every foreign-key constraint in the restored
  database from the information schema (never a hardcoded constraint list), and for each, count
  rows whose referencing columns are non-null but match no parent row. Any non-zero count
  throws, naming the constraint. Additionally require at least one foreign-key constraint to
  exist: zero constraints found means either the schema is wrong or the enumeration is, and
  both must be loud. This is the data-level half of the `DROP TABLE ... CASCADE` lesson; tier 3
  is the constraint-level half, and neither substitutes for the other.
- `assertSequenceState(client, manifest)` — re-project `pg_sequences` and require deep equality
  with the manifest's recorded set, including the set of sequence names.

**Wiring (`scripts/drill.ts`).** Run all four after tier 3, recording their combined result as
the `contentAndReferentialIntegrity` tier. Keep the container stop in the `finally` block.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source dev database → drill process | Schema SQL and row content are read into the drill process as strings for comparison. |
| disposable container → drill process | The restored side's schema dump and query results cross back through `exec` output. |
| manifest file → assertion code | The manifest is the reference every tier compares against; if it is trusted unvalidated, every tier below it is meaningless. |
