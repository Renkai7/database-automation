<objective>
Close the last two open items from `01-VERIFICATION.md`'s Anti-Patterns table, both Info-severity, and
leave the phase's requirement record telling the truth.

WR-03, application half: `recipes.baseServings` carries no positivity constraint, and
`RecipeScreen.tsx` divides by it unguarded to compute the servings multiplier that scales every
displayed ingredient quantity and the calorie label. Today's deterministic seed always sets it to two,
so the defect is latent rather than triggered — but a zero or negative value would render `Infinity` or
`NaN` straight into the page, and the fix is one expression.

Document hygiene: `.planning/REQUIREMENTS.md`'s Phase 1 traceability rows contradict each other —
`ENV-01 … ENV-05` reads one status while `APP-01` on the very next line reads another, for six
requirements in the same phase with the same actual state. `01-VERIFICATION.md` flagged this as a stale
row worth fixing.

**What this plan deliberately does not do.** It does not add the database-level `CHECK` constraint
`01-REVIEW.md` also proposed for WR-03, and it does not mark any requirement complete. Both deferrals
are reasoned below rather than silent.

This plan carries no tracer task of its own by design: the gap set's tracer is plan 01-06 Task 1.

Purpose: `01-VERIFICATION.md` named six findings across four severities. Five are closed by plans 01-06
and 01-07; leaving the last two undone or, worse, silently dropped, would mean the next verification
pass re-discovers them. CLAUDE.md's documentation-is-a-deliverable rule applies to the requirement
table as much as to any other artifact.

Output: a servings scaler that cannot produce a non-finite quantity, and a requirement table that
agrees with itself.
</objective>
