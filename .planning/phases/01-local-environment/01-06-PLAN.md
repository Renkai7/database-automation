<objective>
Close the one blocking gap `01-VERIFICATION.md` found: the "hardcoded to local, no environment
override" architecture D-16 promised does not hold as built. Today `RECIPE_DEV_DATABASE_URL` is
validated only as a well-formed URL, so a one-line `.env` edit repoints `db:query`, `db:reset`, the
app, the seed, and `drizzle-kit migrate` at any reachable host — and `apps/recipe-app/drizzle.config.ts`,
the config driving the most destructive command in the pipeline, performs no environment assertion at
all.

**The shape decision this plan makes, stated rather than assumed.** `01-VERIFICATION.md` offered two
candidate fixes and instructed the planner to pick the one that actually satisfies D-16. D-16 reads:
*"there is no argument, flag, or environment override that redirects it at another database. Repointing
it requires editing source in a diff, not passing a parameter."* A loopback-only hostname allowlist
alone does **not** satisfy that sentence — it bounds the blast radius to the local machine but still
lets `.env` redirect the tooling from `recipe_dev` on port 5432 to a different database on a different
local port, which is literally "another database" reached through an environment override. The weaker
option is therefore rejected.

This plan implements the stronger shape: **the target-identifying components of the connection —
host, port, and database name — become source-level constants in `scripts/env.ts`, and the environment
variable is required to match them.** Only the credential components (user and password) remain
free in `.env`. That is `01-VERIFICATION.md`'s missing item #3 and `01-REVIEW.md` CR-01's own final
recommendation ("the URL, at least host and port, needs to be a constant in source, with only the
password sourced from environment"), and it satisfies D-16 literally: after this change, repointing at
another database requires editing `scripts/env.ts` in a reviewable diff.

Two things this shape deliberately preserves. `RECIPE_DEV_DATABASE_URL` keeps existing and keeps its
name, so D-19's per-environment variable naming and ENV-03 are untouched and `.env.example` keeps its
current shape. And D-21's post-connect `current_database()` assertion stays exactly as it is — the new
check is a *pre-connect* companion to it, not a replacement, so a correctly-shaped URL pointing at a
tampered server is still caught after connecting.

The ergonomic consequence is real and intended: a developer who wants Postgres on a different local
port can no longer just edit `.env`. That is the point. The constants are named and co-located so the
required source diff is a two-line change that a reviewer cannot miss.

Purpose: CLAUDE.md's first non-negotiable is architectural enforcement over remembered caution, and
this is the phase that was supposed to make "no production database access from the local machine"
structural so later phases do not re-litigate it. As built it leans on `.env` being correctly
populated by a human or an agent with file-write access, which is precisely the pattern the
non-negotiable forbids.

Output: a development target that is defined in source and enforced pre-connect in every process, the
migrate path brought under the same guard as the CLI scripts, and a guardrail suite that catches the
regression of both.
</objective>
