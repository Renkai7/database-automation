<objective>
Close the two Warning- and Info-severity items `01-VERIFICATION.md` and `01-REVIEW.md` raised against
the rebuild and query scripts, both of which are the same failure mode as the blocking gap plan 01-06
repairs: a safeguard that exists somewhere other than the tool a person actually runs.

CR-02: `scripts/db-reset.ts` step 4 shells out to `drizzle-kit migrate` and treats a zero exit code as
proof the migration history applied. The independent verification that would catch a silent no-op —
the known Windows failure mode where `drizzle-kit migrate` exits zero without applying SQL — exists
only in `tests/db-reset.test.ts`. A developer or Claude Code running `pnpm db:reset` directly, outside
`pnpm test`, gets none of it and sees a confident "Complete." This plan folds an equivalent assertion
into the tool itself, and — going beyond the review's proposed inline fix — puts it in its own module
so the guard can be proven red as well as green. A verification that has never been shown to fail is
not yet known to have teeth, and Phase 4's RUN-05 and RUN-06 will want exactly this function.

IN-01: the "print only the error's own message, never the error object" pattern, plus the security
rationale explaining it, is duplicated verbatim across three call sites in two scripts. That pattern is
the mechanism keeping a connection string out of logs — CLAUDE.md's "never log or commit credentials"
in its concrete form — and duplicating a security-sensitive guarantee means a future edit to one site
can silently diverge from the others with no shared point of test coverage.

This plan carries no tracer task of its own by design: the gap set's tracer is plan 01-06 Task 1, which
proves the redirected-target refusal end-to-end before any of this hardening is attempted. These are
its expansion tasks.

**Task order, and why the Info item comes first.** Task 2 creates a fourth error-printing site inside
the rebuild script. Building that site on top of an already-extracted shared helper is strictly cheaper
than adding a fourth duplicate and then extracting four, so IN-01 is done first even though CR-02 is
the more serious finding.

Purpose: CLAUDE.md's first non-negotiable again — if a safeguard depends on someone remembering to run
the test suite separately, it is not a safeguard.

Output: a rebuild command that proves its own result, a migration-state assertion proven in both
directions, and one tested definition of the never-leak-a-credential output rule.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `drizzle-kit migrate` child process → the rebuild's success claim | The rebuild reports completion based on what a separate process's exit code asserted about work this process cannot see |
| script error output → terminal, and any log a CI system later captures | Every error-printing site is a place a connection string could escape |
| `db:reset` → the database's entire contents | The rebuild destroys a volume unconditionally at step 1; every later claim it makes is about state it just recreated |
