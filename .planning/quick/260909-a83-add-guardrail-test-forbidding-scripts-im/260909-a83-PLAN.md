## The tension, and how this plan resolves it

A guardrail banning the pattern would fail against the four imports that exist today. The three
options, and the choice:

**(a) Fix the four imports now.** Rejected — it is the Phase 7 package-extraction decision in
disguise, and the task brief explicitly forbids silently expanding into it.

**(b) A named per-file allowlist** (the `FIXTURE_FILES_WITH_CONNECTION_STRINGS` idiom already in
this file). Rejected as the weaker of the two available shapes: an allowlist exempts *files*, so
a fifth escaping import added to `cli.ts` — an already-exempt file — would still pass. It also
asserts `toEqual([])`, an expected state a completely broken detector satisfies trivially.

**(c) CHOSEN — a frozen debt inventory compared by exact equality.** Record the four escapes as
`KNOWN_PACKAGE_BOUNDARY_ESCAPES`, a map of file → the exact specifier strings it escapes with,
and assert the live scan equals it exactly. This is strictly stronger than (b) on three counts:

1. **No file is exempt.** A second escape in `cli.ts` changes its array from one entry to two and
   fails. An allowlist cannot detect this.
2. **It cannot pass vacuously.** The expected state is non-empty, so a detector broken by a bad
   regex, a renamed directory, or a gitignore change produces `{}` and FAILS. This satisfies the
   non-vacuity requirement structurally, not just via the companion self-check test — and it is a
   property `toEqual([])` gates (assertions 4 and 7 in this file) can never have.
3. **It is a ratchet.** Removing one of the four without shrinking the inventory also fails, with
   a message saying so. The record cannot rot, and it can only ever get smaller.

**On the repo's own unconditional precedent** (the `drizzle-kit migrate` ban at
`tests/guardrails.test.ts:317-334`, whose comment reads "a gate with a second door is not a
gate"): that gate is unconditional because it had **zero** real instances — plan 04-01 reworded
six prose mentions to make it pass clean. It was free. Here, four real code instances exist and
cannot be removed within scope, so unconditional means shipping red, and a red default suite is
the condition under which guardrails get deleted. Option (c) preserves that precedent's actual
intent — no second door — because the inventory is not a door: it is a closed, enumerated,
size-pinned record that fails on any change in either direction.
