package supplies mechanism; the config supplies identity.

Third, the proposed three-layer package shape, split by what each layer actually is rather than
by subject matter. Layer one is an npm package holding the scripts, the assertion mechanism,
the drill harness, and the guardrail test suite — the things a consuming project imports. Layer
two is a scaffold or template for `docker-compose.yml`, the environment-file example, and the
CI workflow once Phase 5 exists — the things a project copies rather than imports, because they
are files that must live in the consumer's own tree. Layer three is a Claude Code plugin or
skill carrying the agent-facing layer: the conventions, the rule against echoing a supplied
value back, the rule against reading `process.env` directly that `tests/guardrails.test.ts`
already enforces, and the slash commands. Say why layer three matters — it is the layer that
makes a new project behave like this one, rather than merely holding the same files. Copied
files without the conventions produce a project that has the tooling and still does the unsafe
thing.

Fourth, what does not transfer. The drill evidence: a passing restore drill in this repository
proves nothing whatsoever about another project, because what a drill proves is that this
specific data, on this specific machine, came back. Every consuming project must destroy and
restore its own real data and time it for itself. The script transfers; the proof never does.

the restore — and note that the consequence re-arms in each new project. Also non-transferable:
the Coolify and Hetzner specifics, and the PostgreSQL major-version pin from D9.

in source with the same reviewable-diff guarantee, so that Phase 3 writes against that config

is not yet done.
